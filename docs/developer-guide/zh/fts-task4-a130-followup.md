# 赛题 4：零分提交后的优化与验证

本轮直接以正式反馈对应的 `a130f500d66d0ace7dbdc60887c478475c22e35c` 为对照。修改减少 IK 仲裁的逐文档分配，以及赛题 3 后台线程在无 AI 定义时的空闲事务。完整同机测试综合耗时下降 **1.40%**，尚没有证据表明足以抵消正式反馈中的 **-20.40%** 综合提升率，不能据此保证正式评测得分。

## 修改依据

- IK 仲裁原来对每篇文本创建哈希桶、插入链节点，再按字节偏移查询；它不遍历哈希表。改为带 16 项内联空间的有序数组，二分查找，通常按序追加，超出容量正常扩容。重复键不覆盖、缺失键不改输出指针，保留原有返回码。分词规则、词典、链选择与输出顺序不变。
- 四个 AI 工作线程原来在空闲时仍各自每 100 ms 领取任务并聚合终态组。没有 AI 列定义时，共用一次每 100 ms 的元数据探测，跳过没有工作的领取事务；有定义时保留四线程领取与执行，并对终态恢复扫描去重。固定线程所有者字符串移到循环外。探测出错保留已有状态，任务租约、重试、发布条件未改。
- 上次 GitHub 构建和原生检查通过，但 MariaDB mysqltest 拒绝 OceanBase 客户端支持的 `--replace_regex /…/…/g`，使后续性能步骤没有运行。运行器现在仅在临时测试副本中去掉冗余 `g`，保留默认全局替换、模式、替换内容、SQL 和原始预期结果；未知或不完整表达式保持原样。补充兼容解析测试。原始验收文件未改。

## 同机完整 A/B
